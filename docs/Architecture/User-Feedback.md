# User feedback and task observations

**Source and period:** The table below contains 14 submitted task surveys dated 15 August–15 September 2026. It records self-reported results and comments for four tasks: getting started, squad/players, coaching workflow and a chosen realistic action. The source does not identify a controlled test environment, facilitator, recruitment method, follow-up retest or stakeholder acceptance. Participant roles are self-described; this is user feedback, not a client sign-off.

## Findings from the recorded responses

| Finding | Evidence in responses | Priority and follow-up |
| --- | --- | --- |
| Team setup is unclear before roster access | Several respondents say locked roster/team tabs were confusing until they created a team. | [Trello onboarding issue](https://trello.com/c/3w1GG5Qf). A tooltip was suggested; implementation and retest are not established by this survey. |
| Roster entry is slow | Multiple respondents mention adding players one by one as the weakest part. | Workflow improvement; bulk entry is not evidenced here. Record a distinct card before claiming this is scheduled work. |
| Injury eligibility concern | One coach/assistant respondent reported that injured players could still be selected. | Compare with [squad eligibility issue](https://trello.com/c/Ea2RUO8v) and [team-management status issue](https://trello.com/c/poV9l0zN). Retest the current build before closing either card. |
| Roster statistics did not refresh after live logging | One player respondent reports stats not updating on the roster page. | Compare with [roster statistics issue](https://trello.com/c/UyOQVbi7); reproduce on an identified revision before closing. |
| Database timeout during starting task | One respondent reports a database connection timeout and rated it major. | Operational failure in that session; no root cause or current production status is established. |
| League and comparison expectations | Respondents requested joining leagues, defensive statistics and other event types. | Product gaps to compare with the brief and backlog, not accepted requirements by themselves. |

The forms include satisfaction ratings and task times, but device type, build hash and measurement method are missing. Do not treat the times as performance benchmarks or the positive ratings as proof of accessibility. The table is preserved as original evidence; avoid republishing participant contact details if a richer source export is later attached. Current source changes may address some findings, but no follow-up user session is recorded here. The linked cards show related tracker items, not confirmed fixes or exact one-to-one survey issue IDs.
